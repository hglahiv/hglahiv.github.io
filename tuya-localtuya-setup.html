Tuya + LocalTuya Setup Guide

🔌 Example device: ELEGRP PQR20 🔗 Protocol: LocalTuya (no cloud) 📅 Last verified: May 2026
tuya localtuya home-assistant smart-plug elegrp iot-vlan

📋 Overview

This guide covers adding a Tuya-based WiFi smart plug (e.g. ELEGRP PQR20) to Home Assistant using the LocalTuya integration for fully local control with no cloud dependency.

ℹ️ Why LocalTuya
LocalTuya communicates directly with the device on your LAN — no cloud round-trip after setup. The native Tuya cloud integration is an easier alternative if local control isn't required.

✅ Prerequisites

  • Home Assistant with HACS installed
  • LocalTuya installed via HACS
  • The plug paired and online in its native app (e.g. ELEGRP Home, Smart Life, Tuya Smart)
  • A free Tuya IoT Platform developer account

📱 Step 1: Re-pair the Plug in Smart Life

If the plug is currently paired in a white-label app (e.g. ELEGRP Home), you need to move it to the Smart Life app so it surfaces in the Tuya developer portal.

Smart Life is the official Tuya-branded consumer app (published by Tuya Inc). Many smart home devices ship with white-label versions of this app under different names — but Smart Life is the one that integrates cleanly with the Tuya developer portal.

  1. Reset the plug

    Hold the button until it blinks rapidly.

  2. Download the Smart Life app

    iOS / Android — then create or log in to an account.

  3. Pair the plug in Smart Life

    Add it as a new device.

ℹ️ Why?
White-label Tuya apps (like ELEGRP Home) don't reliably expose device credentials in the developer portal. The official Smart Life app does.

☁️ Step 2: Set Up a Tuya Developer Project

✅ Already complete for the GHouse setup
The Tuya developer project "Elegrp" is created, APIs are subscribed, and the Smart Life account is linked. These steps are here for reference if you ever need to recreate it.
  1. Log in at platform.tuya.com

    platform.tuya.com

  2. Create a Cloud Project

    Cloud → Development → Create Cloud Project

    • Region: Western America (for US devices)
    • Industry: Smart Home
    • Development Method: Smart Home
  3. Confirm Service APIs are subscribed
    • IoT Core
    • Smart Home Basic Service
    • Authorization Token Management
  4. Link the Smart Life app account

    Devices → Link App Account → Add App Account, then scan the QR code using the Smart Life app (Me → Scan).

  5. Verify devices appear

    Your devices should now show up under the project's Devices tab.

🔑 Step 3: Get the Device ID and Local Key via tinytuya

The Tuya developer portal doesn't always surface the Local Key in the UI. Use the tinytuya Python tool to pull it directly from the cloud API.

On your Mac (recommended — Python and pip are simpler on macOS than Windows). Open Terminal:

pip3 install tinytuya
python3 -m tinytuya wizard

When prompted enter:

  • API Key: your project's Access ID (Overview tab in portal)
  • API Secret: your project's Access Secret (Overview tab)
  • Region: us

Skip the local network scan if the device is on an IoT VLAN (UDP broadcasts won't cross VLANs). The wizard pulls credentials from the cloud regardless.

When complete, open the generated devices.json file and find your device. Note the:

  • id → Device ID
  • key → Local Key
  • version → Protocol version (typically 3.3 or 3.4)
⚠️ Important
The Local Key changes every time you reset and re-pair the device. If you ever reset the plug, re-run the tinytuya wizard to get a fresh key.

🌐 Step 4: Find the Device IP

Check your router/UniFi controller for the plug's local IP address. If it's on an IoT VLAN, note the VLAN IP (e.g. 192.168.5.x).

➕ Step 5: Add the Device in LocalTuya

  1. Open LocalTuya configuration in HA

    Settings → Devices & Services → LocalTuya → Configure → Add Device

  2. Enter device credentials
    • Host: local IP address from Step 4
    • Device ID: from devices.json (also visible in the Tuya developer portal under your project's Devices tab)
    • Local Key: from devices.json (portal does not reliably show this — use tinytuya)
    • Protocol Version: from devices.json — use 3.4
    ⚠️ The UI defaults to 3.3 — make sure to change it if your device is 3.4.
  3. Add a Switch entity
    • Platform: Switch
    • DPS ID: 1 (single outlet) or 1 and 2 (dual outlet)
    • Friendly name: e.g. Landscape Lighting

🩺 Step 6: Verify

The plug should now appear as a switch entity in HA (e.g. switch.landscape_lighting). Test on/off from the HA UI to confirm local control is working.

✅ Success
Switch responds instantly with no cloud round-trip. Pull the WAN cable and toggling still works — confirming local control.

⏰ Step 7: Create an Automation (Optional)

Example: turn on at sunset (15 min early), off at sunrise.

alias: Landscape Lighting
description: Turn on landscape lights at sunset, off at sunrise
mode: single
trigger:
  - platform: sun
    event: sunset
    offset: "-00:15:00"
    id: sunset
  - platform: sun
    event: sunrise
    id: sunrise
action:
  - choose:
      - conditions:
          - condition: trigger
            id: sunset
        sequence:
          - action: switch.turn_on
            target:
              entity_id: switch.landscape_lighting
      - conditions:
          - condition: trigger
            id: sunrise
        sequence:
          - action: switch.turn_off
            target:
              entity_id: switch.landscape_lighting

🔧 Troubleshooting

⚡ Device not found in Tuya portal

Use the Smart Life app instead of the white-label app, then re-pair the device. White-label apps don't reliably expose credentials in the portal.

⚡ LocalTuya won't connect

Confirm the IP is correct (check UniFi). Try protocol 3.3 instead of 3.4 — different firmware revisions use different versions.

⚡ Entities not responding

The Local Key may be stale — re-run the tinytuya wizard after any re-pair to pull a fresh key, then update the LocalTuya config.

⚡ tinytuya scan shows "No IP found"

The device is on an IoT VLAN — skip the scan. The keys are pulled from the Tuya cloud regardless of local network reachability.

⚡ QR code goes invalid immediately

Expected — the QR code in the developer portal is single-use. Check the portal for the linked account; if it shows up, you're good.

📖 Notes

  • LocalTuya communicates directly with the device on your LAN — no cloud dependency after setup.
  • Place the plug on the IoT VLAN (VLAN 5) and ensure HA can reach that subnet.
  • The native Tuya cloud integration is an easier alternative if local control isn't required.

Govee Matter Pairing Guide

📦 Model: H6022 🔗 Protocol: Matter over WiFi 📅 Last verified: May 2026
govee matter home-assistant apple-home ipv6 udm-se

📋 Overview

This guide documents the confirmed working process for pairing a Govee H6022 lamp to Home Assistant via Matter, using Apple Home as the primary commissioner and HA as a secondary controller via Multi-Admin.

⚠️ Hard-won knowledge
This procedure took two days to figure out. The order of operations matters — deviating from these steps (especially the power sequence and network requirements) will result in pairing failures.

✅ Prerequisites

Network Requirements

Matter over WiFi requires IPv6 SLAAC to complete commissioning. Before starting, verify:

  • UDM SE is handing out IPv6 addresses on the Default VLAN
  • Other Default VLAN clients show IPv6 addresses in UniFi
  • Phone must connect to 92108-2g (Default VLAN 2.4GHz — NOT IoT SSID)
ℹ️ Why 2.4GHz Default VLAN specifically
Matter's BLE → WiFi handoff during commissioning requires the phone and device to land on the same network segment. The IoT SSID is also 2.4GHz but commissioning fails on it. Use the main Default VLAN 2.4GHz SSID only.

App Requirements

  • Govee Home app — must be installed AND logged in (not just open). Login triggers the BLE pairing flow.
  • Apple Home app — used as the primary Matter commissioner
  • HA Companion app — for the Multi-Admin secondary pairing

🔗 Pairing Steps

⏱️ Time limit
After factory reset, you have approximately 15 minutes to complete commissioning before the window closes. Have all apps ready before you start.
  1. Unplug the lamp

    Physically unplug from the wall. Wait 5 seconds.

  2. Plug the lamp back in

    Let it fully boot — wait for it to stop its startup light sequence.

  3. Factory reset

    Hold the power button on the lamp, then click the − (minus) button 4 times while holding power. The lamp will flash to confirm the reset.

    ⚠️ Order matters: power must be on first, THEN reset. Resetting while unplugged doesn't work.
  4. Open Govee Home app and confirm logged in

    Don't just open it — verify you're actually logged into your account. The BLE pairing flow requires an active session.

  5. Connect phone to 92108-2g

    Default VLAN 2.4GHz network only. Not IoT, not 5GHz.

  6. Get the Matter QR code from the Govee app

    In Govee Home → find the lamp → Settings → Matter → Show QR Code. This is the Matter-specific code, not the generic setup QR on the bottom of the lamp.

  7. Add to Apple Home

    Apple Home → + → Add Accessory → scan the QR code from the Govee app. Follow the prompts. The lamp should commission to Apple Home successfully.

  8. Add to HA via Multi-Admin

    In Apple Home → long-press the lamp → Turn on Pairing Mode. This opens a new commissioning window and provides a new pairing code.

    Then in HA Companion app → Settings → Devices & Services → Add Integration → Matter → enter the pairing code from Apple Home.

✅ Success indicators
The lamp appears in HA under the Matter integration. State updates are near-instant when physically toggling the lamp. Entity ID: light.govee_lamp

🔧 Troubleshooting

⚡ Lamp goes unavailable in HA / Matter CASE session timeouts

First check: Does the lamp have an IPv6 address in UniFi client list?

If no IPv6 → the UDM SE's RA daemon (dnsmasq) has stopped broadcasting Router Advertisements. This is caused by memory pressure on the UDM SE killing the RA process.

Fix: Reboot the UDM SE from the UniFi UI. After reboot, IPv6 addresses will be re-assigned via SLAAC and Matter connectivity will restore within a few minutes.

Root cause: High memory usage (IPS/Suricata was the culprit — disabled in favor of Pi-hole + VLAN segmentation).

⚡ Pairing fails — Apple Home can't find the lamp

Check 1: Is the phone on 92108-2g (Default VLAN 2.4GHz)? Not IoT, not 5GHz.

Check 2: Are you logged into the Govee app (not just open)?

Check 3: Does the lamp have an IPv6 address in UniFi? If not, reboot the UDM SE first.

Check 4: Was the factory reset done in the correct order? Unplug → plug in → THEN reset.

⚡ Matter log shows repeated CASE session timeouts (Node 25)

This means the device's fabric credentials are stale — the Matter Server and device have mismatched keys.

Fix: Full re-pair required. Remove the device from Apple Home and HA Matter integration, then follow the pairing steps from the top.

Check Matter Server logs: Settings → Add-ons → Matter Server → Logs

CASESession timed out while waiting for a response
from peer <0000000000000019, 1>
⚡ UDM SE memory pressure / earlyoom killing processes

Check available memory via SSH:

free -m

Available should be above 800MB comfortably. If below ~500MB, check what's consuming memory:

ps aux --sort=-%mem | head -10

Known fix: IPS/Intrusion Prevention was disabled — it ran Suricata at ~500MB RAM constantly and earlyoom would kill the RA daemon when memory got tight. Pi-hole + VLAN segmentation provides sufficient protection without IPS overhead.

🩺 Health Checks

Run these from the UDM SE SSH session if Govee/Matter devices start dropping.

Check IPv6 prefix delegation from AT&T
ip -6 route show | grep -v fe80

Should show /64 subnets for each VLAN bridge (br0, br3, br5, br6, br7, br99)

Check RA daemon (dnsmasq) is running
ps aux | grep dnsmasq | grep -v grep

If no output → reboot UDM SE from UniFi UI

Check UDM SE memory health
free -m
ps aux --sort=-%mem | head -10
Check Matter Server logs in HA
Settings → Add-ons → Matter Server → Logs

Look for CASE session errors referencing specific node IDs

📖 Background & Architecture

Govee H6022 lamps are paired via Matter over WiFi using a Multi-Admin setup — Apple Home acts as the primary commissioner, and HA joins as a secondary controller. This avoids depending on Govee's cloud integration.

The Matter fabric is managed by the Matter Server add-on in HA. Each device gets a Node ID in the fabric. The UDM SE handles IPv6 prefix delegation from AT&T via odhcp6c, and distributes Router Advertisements to VLANs via dnsmasq.

ℹ️ Why IPS was disabled
The UDM SE runs Suricata for IPS, which consumed ~500MB RAM constantly under the suricata_ubios_high.yaml profile. Combined with the UniFi controller (Java, ~700MB) and MongoDB (~360MB), the system regularly ran below 500MB free. earlyoom would kill dnsmasq or related processes under pressure, dropping IPv6 RA and taking Matter devices offline. IPS was disabled in favor of Pi-hole DNS filtering + VLAN segmentation, which provides equivalent protection without the memory overhead.
